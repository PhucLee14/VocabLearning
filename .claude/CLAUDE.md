# Godee (repo: Vocab) – project notes for Claude Code

Multi-user English vocabulary learning web app, named **Godee** (renamed from "Vocab" on 2026-11-03; folders, package names, the `vocab_session` cookie and DB names keep "vocab"). Production frontend: https://godee.vercel.app. Plan: `PLAN.md`. Deployment: `docs/DEPLOYMENT.md`. Word data sources: `docs/DATA_SOURCES.md`.

## Language

- The user writes in **Vietnamese**: reply to them in Vietnamese.
- **Everything in the repo is English**: docs (`PLAN.md`, `README.md`, `docs/`, this file, the work log) and code comments, test names and log/error messages.
- Exceptions: UI text in `frontend/messages/vi.json` and Vietnamese data (e.g. `nameVi` in `backend/prisma/seed/topics.json`, `meaning_vi` in import samples).

## Architecture

- `frontend/`: Next.js 16.4 (App Router, Turbopack, Cache Components + Partial Prerendering on by default), Tailwind 4, next-intl 4. Port **3300**.
- `backend/`: NestJS 12 (**ESM**: `"type": "module"`, relative imports need a `.js` extension), Prisma 7 + `@prisma/adapter-pg`. Port **4300**, every route under `/api`.
- Database: Neon Postgres 18 in **Singapore** (`aws-ap-southeast-1`).
  - `DATABASE_URL` (pooled) is used at runtime.
  - `DIRECT_URL` (direct) is used by the Prisma CLI.
- Ports in use by the user's other projects: 3000–3002, 4000 (`forge tunnel`), 5000, 5173, 8000, 8080. This app uses **3300/4300** (moved from 3100/4100 on 2026-11-02 at the user's request); don't switch back.
- **Hosting: Vercel Hobby (free)** for both apps, region `sin1` (`vercel.json` in each app), Node `24.x` (`engines`). See `docs/DEPLOYMENT.md`.
  - The backend runs as a **serverless Vercel Function** (NestJS zero-config, entry `src/main.ts`).
    - Do not rely on in-process cron (`@nestjs/schedule`), timers or background work after the response is sent.
    - `src/main.ts` must call `bootstrap()` **without** a top-level `await`. Vercel's launcher stubs `http.Server.listen` (the callback never fires) and waits for the module to load, so `await bootstrap()` hangs every request with no logs (production outage on 2026-11-12).
    - Max 300 s per request; 4.5 MB request/response bodies.
    - Scheduled work = HTTP endpoints protected by `CRON_SECRET`, triggered by Upstash QStash.
  - The browser calls same-origin `/api/*`; `frontend/next.config.ts` rewrites it to `API_URL` (read at build time). Server Components call `API_URL` directly (`src/lib/api.ts`).
  - Migrations are not run in the Vercel build: use `npm run db:migrate` / `db:deploy` from the dev machine.
  - Hobby is non-commercial only.

## Technical gotchas

- **Next.js 16 differs from training data**: read `frontend/node_modules/next/dist/docs/` before writing Next code (see `frontend/AGENTS.md`).
  - `middleware.ts` is now `proxy.ts`.
  - Read the locale with `next/root-params`.
  - With Cache Components, uncached data (API fetches, cookies) must sit inside `<Suspense>` or use `'use cache'`.
- **UI design** (friendly learning-app look, 2026-11-03; replaced the earlier "reference manual" look):
  - Tokens live in `frontend/src/app/globals.css` and map to Tailwind colors: `sky`, `sun`, `moon`, `water` (3D island scene only), `canvas` (page), `surface` (pale green panels), `raised`, `sunken`, `ink`, `muted`, `line`, `line-strong`, `accent` (+ `accent-lip`, `accent-soft`, `accent-ink`, `on-accent`), `streak` (+ `-soft`), `danger` (+ `-soft`), `warning-soft`/`warning-ink`, and the mastery ramp `m0`–`m5`. Use these, not raw hex or Tailwind palette colors.
  - One font: Nunito (`font-sans`, Vietnamese subset). No monospace in the UI; numbers use `.num` (tabular figures).
  - Shared classes in `@layer components`: `.btn` + `.btn-primary|secondary|danger|ghost` (+ `.btn-lg|sm`; pill with a solid lip, no shadow), `.panel` (tonal panel), `.card` (white card, 1px line), `.pill` (+ `-accent|-streak|-danger`), `.chip` (pressed = `aria-pressed="true"` or `aria-current="page"`), `.seg` (segmented control), `.input`, `.field-label`, `.num`. Flashcard flip: `.flip`, `.flip-inner[data-flipped]`, `.flip-face`, `.flip-back`.
  - House rules: flat surfaces (a tone step or a 1px line, never a resting shadow), no gradients, no emoji, colour on data (mastery ramp, today's bar, streak) and on the one primary action.
  - Element defaults must stay inside `@layer base`: unlayered CSS beats every Tailwind utility.
  - Theme: Light / Dark / System. Stored in `localStorage` (`theme`), applied as `data-theme` on `<html>` by an inline script in `<head>` (`src/lib/theme.ts`, `src/components/inline-script.tsx`), so pages stay static and there is no flash. No `data-theme` = follow the OS. Don't move it to a cookie (that would make every page dynamic).
  - Layout: `src/app/[locale]/(site)/` = public pages with the site header; `src/app/[locale]/(app)/` = the app shell (sidebar ≥1024px, top bar + bottom bar below). Wrap page content in `<Page>` from `components/shell/app-shell.tsx`.
- **3D island** (PLAN.md Phase 3d): behind the landing page (`(site)/page.tsx`) and on the lab page `/[locale]/lab/island` (`noindex`, not linked, shows fps / draw calls). Code: `frontend/src/components/island/`.
  - Landing sections are "floors": `<IslandStop stop="hero|try|how|levels|topics|close">` (`stop.tsx`), one camera stop each (`STOPS` in `scene.tsx`, same order). Content sits in a 520px column: from 1280px beside the island, text left on even floors and right on odd ones (the island is opposite); below 1280px a panel at the bottom with the island above.
  - The 1280px breakpoint lives in four places that must stay in sync: Tailwind `xl:` in `stop.tsx`, `WIDE_LAYOUT` in `scene.tsx`, `WIDE` in `floor-scroll.ts`, and the mandatory scroll snap in `globals.css`.
  - One scroll gesture = one floor: CSS scroll snap on `html:has([data-island-stop])` (mandatory from 1280px, proximity below; the site header is the first snap point and the footer the last), plus `useFloorWheel` (`floor-scroll.ts`) on wide screens, because CSS snap alone returns to the same floor after a single ~100px wheel notch.
  - Camera: it orbits the island (`STOPS` = angle, elevation, radius per floor) and always shows the **whole** island in the free part of the screen. Don't reintroduce close-ups: the rest of the island then sits under the text panel (user feedback 2026-11-14).
  - Sky bodies (`celestial.ts`): sun + rays in the light theme, crescent moon + stars in the dark theme (`palette.dark`, read from the computed `color-scheme`). Sun and moon are children of the camera (fixed place on screen, on the island's outer side) and drawn without depth test between the cloud sea and everything else (`renderOrder`: sea 0, stars 0.5, sun/moon 1–1.2, clouds 2, island 3); keep them opaque (a transparent material would be drawn after the island). They sit at opposite ends of an unseen wheel: a theme change turns it half a turn (over `THEME_FADE_SECONDS`), one setting inwards, towards the island, while the other rises from the outer side of the screen (the other direction was tried and read as backwards); reduced motion swaps them at once. Stars are a world-fixed dome. The directional light (`skyLight`) follows the body's side; its colour and strength are set per theme in `scene.tsx`. Colours: `--sun`, `--moon` in `globals.css`. Keep camera elevations ≤ ~22°, or the top of the screen shows cloud sea instead of sky.
  - Theme change = a fade, not a cut (`THEME_FADE_SECONDS` in `src/lib/theme.ts`, 2.2 s). In the scene (`ThemeFade` in `scene.tsx`): the sky, fog, clouds, light colour and levels ease from their old values to the new; the island's material blends two sets of vertex colours (`colorFrom` → `color`, uniform `themeBlend`, patched in with `onBeforeCompile`), so every geometry drawn with that material needs `colorFrom` and a normal (`Builder.build` sets them, `fadeFrom` fills `colorFrom` with the last theme's colours). On the page: `setTheme` puts `theme-fading` on `<html>` for that long, and `globals.css` gives every colour a long transition while it is there, on pages with the island only; surfaces take the whole time, text and icons flip quickly in the middle (faded slowly they pass through the colour of the surface behind them). Reduced motion: no fade anywhere.
  - Scenery (`scenery.ts`): the scene draws its own sky (`scene.background` is the fog's colour object, so the two always match; the `--sky` token on the fixed wrapper only shows until the scene has loaded); the cloud sea (instanced puffs + a disc, at y = -24; finer spheres near the island than far away) and the distant clouds are instanced, the birds one dynamic geometry. Clouds use `cloudMaterial` (`scenery.ts`): matt, lit per corner instead of per pixel. Keep clouds out of the camera's sight lines (far ring, above the sea) and birds inside the camera's orbit (it stays ≥ ~20 units from the island's axis).
  - The island is a **village** (user's choice, 2026-11-14), not "one building per topic": 8 houses, one per part of speech (`parts.ts`, labels `Island.pos_*`), along a path; a lake; a craggy mountain with a trail winding up to the summit and six level flags (A1 at the foot … C2 on top); a waterfall down the mountain into the lake; a stream that falls off the rim; two bridges; a field; a windmill; a camp. All positions are constants in `geometry.ts`; when adding something, check it against the lake, the stream, the paths, the mountain (up to 5.1 around `MOUNTAIN` at the foot, plus the trail) and the stepping stones. The grass is flat at y = 0 with an uneven rim (`rimRadius`, never under 9.8). Kit facts: houses have their door on the **-z** side, the bridge is walked along its **x** axis (rails on its ±z sides, deck 0.15 up; checked triangle by triangle 2026-11-16, the earlier note said z and both bridges lay along the water), nature models sit 0.05 below their origin. Water colour: `--water`.
  - Mountain (`geometry.ts`): its shape is set by rings of 12 corners (`MOUNTAIN_RINGS`, `MOUNTAIN_CORNERS`) at the same 12 angles, each corner pushed in or out by a hash of its place, so it looks the same on every visit. What is drawn is the smooth surface through those corners with smaller lumps on it (`rockFace(columns, level)`), as a grid (`MOUNTAIN_GRID`, 4 pieces per column and per ring). The two columns either side of the waterfall are left equal and the face runs straight between them, without lumps: the water lies on it exactly (`cascade` follows the same grid rows). Anything else laid on the rock goes through `onMountain(angle, height, out)`, which is on the true surface, very near the drawn grid but not exactly on it: let it reach a little into the rock (the trail's inner edge does).
  - Separate meshes: the water (`buildWater` in `geometry.ts`, drawn by `createWater` in `water.ts`), the windmill's blades (`buildBlades`), the actors (`actors.ts`: canoe, fish, campfire flame, hidden mushrooms, the night lantern's point light), the people (`people.ts`) and the ambience (`ambience.ts`: campfire smoke, spray where water lands, fireflies at night; all are points drawn as soft dots).
  - Water (`water.ts`; user feedback 2026-11-16: it was "thin, without movement or depth"): running water is five strips wide and arched (`STREAM_SWELL`, `FALL_SWELL`), so it has a body; the fall off the rim is an arc (`RIM_FALL`) that thins out into ragged streaks (`flow`'s 4th number + `discard`). The material works the colour out per pixel: the lake shows a bed (sand, stones, caustic lines) shifted by the angle of view and covered by the water's colour with depth (`shore` = 1 at the edge … 0 in the middle); running water has a slow broad layer and a fast fine layer of streaks. Spray comes from `SPLASHES` (`geometry.ts`). There are no foam-streak quads any more (they read as road markings).
  - People (`people.ts`, requested 2026-11-16): eight round figures made of stretched spheres, all parts of all people in one `InstancedMesh` (plus a box for the book); no kit models. Each frame a pose (leg and arm angles, lean, seat) is turned into the parts' matrices (`figure`). Who does what and where: `PEOPLE_SPOTS`, `WALKS`, `trailWalk`, `BRIDGES` in `geometry.ts` (walkers step up onto a bridge's deck). A click makes a person wave (`Kind` `'person'`, targets are `people.spots`). Their colours ease with the theme through `update`'s `blend`.
  - Quality guard (`scene.tsx`, `DPR_CAPS`, `SLOW_FPS`, `SLOW_SECONDS`): when a page view keeps running under 40 fps for 4 s the pixel ratio cap goes down a step (1.5 → 1.25 → 1 → 0.8), then the shadows go; it never goes back up in that page view. So a read-out of a lower `dpr` on the lab page, or missing shadows in a software-rendered test, is the guard at work, not a bug.
  - Interaction (`scene.tsx`): the canvas still takes no pointer events; the scene listens on `window` and ignores the pointer while it is over content (`overPage`: links, buttons, `[data-island-ui]`, header, footer; `IslandStop` marks its content with `data-island-ui`). Picking is ray-against-sphere over a list of targets (`FIXED_TARGETS` + canoe, mushrooms, people, birds), then the lake's and the ground's level; the mountain has blocker spheres (`rock`). A sideways drag turns the island (`touch-pan-y` on the floors lets the browser keep vertical scrolling), a click reacts, hover shows a label, a double click zooms in on that spot. Zoom steps are `ZOOM_STEPS` in `parts.ts`. Three ways to zoom: the page's buttons (they ask the scene with a window event, `requestZoom`), a double click, and Ctrl + wheel over the bare island (a trackpad pinch arrives as the same event; `WHEEL_PER_ZOOM_STEP`), which zooms towards the pointer. The plain wheel must stay with the floors (`floor-scroll.ts` ignores Ctrl + wheel): the island fills half the screen, and an island that swallowed the wheel would trap everyone scrolling with the pointer on it (decided with the user 2026-11-16). `island.tsx` shows a one-time hint when a mouse first rests on the island. The mountain's blocker spheres must stay inside the rock, or things standing on it (flags, the trail's mushroom) can't be clicked. `island.tsx` owns the two pieces of HTML: the label that follows the pointer and the mushroom count. On the lab page `window.__islandTargets()` returns every target's screen position (for tests). `island.tsx` is in the page's first script: never import `geometry.ts` or anything else that imports three into it (hence `parts.ts`).
  - Models (`kit.ts`, `geometry.ts`): houses, trees, rocks, plants, props and the windmill come from three CC0 Kenney kits, baked by `npm run island:kit -- --city <dir> --nature <dir> --hexagon <dir>` (`frontend/scripts/island-kit.mjs`, takes about half a minute) into `public/models/island-kit.bin`; sources and licences in `docs/ASSETS.md`. The file stores positions, a colour **role** and an ambient-occlusion byte per vertex (no colours, normals, UVs or textures); `roleColors` maps roles to tokens, so models follow the theme. `ROLES` must be identical in the script and in `kit.ts` (the loader refuses a mismatch). When the kit is loaded each model is reworked once (`refine` in `kit.ts`, helpers in `mesh.ts`): corners get normals, shared across edges flatter than the role's crease angle (`CREASE`), and the leaves of trees and bushes are split into smaller triangles on a rounder surface (`tessellate`). If the kit fails to load the island falls back to plain shapes. Record every new asset's licence in `docs/ASSETS.md`.
  - Look (user's choice 2026-11-15: round and lit, not faceted; the one place where the UI's "flat, no shadows" rule does not apply): the island is one merged mesh, three corners per triangle with nothing shared, each corner with its own normal (`creasedNormals` in `mesh.ts`: smooth where faces meet at less than the crease angle, an edge otherwise), a vertex colour and `extra` (how far it sways in the wind, whether it glows at night). Outlines are smooth curves through the layout's points (`roundLoop`, `roundLine`, `around`): to change a shape, move or add layout points. Light: a `HemisphereLight` (the sky from above, the ground's bounce from below) plus the sun's / moon's `DirectionalLight`, which casts the shadows (one 2048 map, 1024 on touch devices, laid ±16.5 around the island's axis; `LIGHT_FROM_VIEWER` keeps the light mostly sideways, so shadows fall across the ground, not behind the things that cast them). The island's material (`scene.tsx`, `onBeforeCompile`) adds the theme fade, the wind and the lit windows to the stock matt material; the water's (`water.ts`) adds ripples, the sky's colour at a flat angle and foam at the shore (its geometry's `flow` and `shore`). No tone mapping: the sky is the clear colour, which is not tone-mapped, so the fogged cloud sea would stop matching it. A theme change only works out colours again (`Frame` in `geometry.ts` keeps the rest from the last build: about 100 ms → 14 ms). Measured 2026-11-15 on this machine's integrated Radeon, headless: about 130 fps at 1600×900 ×1, 60–75 fps at 1920×1080 ×1.5; shadows cost about a tenth, the resolution decides the rest.
  - Plain `three`, **no `@react-three/fiber` or drei**: fiber pulls in all of three (245 KB gzip vs 136 KB). Import named exports from `'three'` only.
  - `island.tsx` (client wrapper) loads `scene.tsx` with `next/dynamic` (`ssr: false`) once the page is idle, and writes scroll progress into a ref from the `data-island-stop` sections; `scene.tsx` owns the renderer and the frame loop; `geometry.ts` lays out and builds the island; `palette.ts` reads the CSS tokens (follows the theme live).
  - The canvas is fixed behind the HTML, `aria-hidden`, `pointer-events-none`. Page sections stay normal HTML.
  - Lab aid: `#p=2.5` in the URL pins the camera progress (for screenshots).
  - Headless screenshots on this machine: `puppeteer-core` with the installed Chrome. `--enable-gpu --ignore-gpu-blocklist --use-angle=d3d11` renders on the real GPU (full frame rate, so fps read-outs mean something); `--enable-unsafe-swiftshader --use-angle=swiftshader` renders in software at 3–4 fps. Judge shadows and other soft detail on enlarged crops (`clip` with `scale`): in a full frame scaled down they cannot be seen (an hour was lost on "missing" shadows that were there). Chrome's own `--screenshot` with `--virtual-time-budget` often fires before the scene loads.
- **Auth** (`backend/src/auth/`): database-backed sessions, not JWT. Google sign-in: `auth/google.ts` (server-side OAuth code flow + PKCE, `jose` checks the ID token); the callback is `<first FRONTEND_URL>/api/auth/google/callback`, and Google-only accounts have no password (`hasPassword` in `/me`); they confirm set-password and delete with a 6-digit **email code** (`POST /me/confirm-code`, `auth/confirm-code*.ts`, `AuthToken` type `ACTION_CONFIRM`). Cookie `vocab_session` (httpOnly, SameSite=Lax, `secure` when `NODE_ENV=production`), 30 days sliding, at most 90 days after sign-in. Server Component fetches send `x-vocab-ssr: 1` and never extend the session (their `Set-Cookie` can't reach the browser); the browser's `SessionKeepAlive` pings `GET /api/auth/session` instead. Guards: `SessionGuard` (401) and `OptionalSessionGuard`; `@CurrentUser()`. Wrong password on a signed-in action is **403**, not 401 (the client treats 401 as "signed out").
  - Frontend: Server Components read the user with `src/lib/server-api.ts` (`userGet` forwards the cookie and redirects to `/login` on 401; `optionalUserGet`; `getViewer`); Client Components call `src/lib/client-api.ts` (`api()`), then `router.refresh()`. Reading the session is dynamic: keep it inside `<Suspense>`.
  - Client hooks that read the URL (`usePathname`, `useSearchParams`) must sit inside `<Suspense>` too, or `next build` fails on dynamic routes (see `components/locale-switcher.tsx`).
  - ICU lists canonical time zone names (`Asia/Saigon`), not the stored alias (`Asia/Ho_Chi_Minh`): a time zone `<select>` must include the stored value.
- **i18n**: routes live under `src/app/[locale]/...`, config in `src/i18n/`. New UI text goes into **both** `messages/vi.json` and `messages/en.json`. Keys are type-checked via `src/global.d.ts`.
- **Prisma 7**:
  - CLI config is `backend/prisma7.config.ts` (Prisma 7 looks for this filename).
  - The client is generated into `backend/src/generated/prisma/`; import from `../generated/prisma/client.js`.
  - The npm `latest` tag of `prisma` points to **8.0.0-rc**: always pin `prisma@7.x` and `@prisma/client@7.x`. The prisma.io docs now describe Prisma 8 ("contract" based), which does not apply here.
- **Health check**: `/api/health` must not query the DB, so Neon Free can scale to zero. `/api/health/db` needs `Authorization: Bearer <CRON_SECRET>` (404 otherwise).
- **CSRF** (`backend/src/common/http-security.ts`, runs before every route): a POST/PUT/PATCH/DELETE is refused when `Sec-Fetch-Site: cross-site`, when `Origin` is present and not in `FRONTEND_URL` (`null` included), or when it has a body that is not `application/json` (415). New write endpoints must take JSON; a webhook from another site would need an explicit exception there.
- **CSP** (frontend, `csp` in `frontend/next.config.ts`): `default-src 'self'` plus explicit directives. Loading anything from a new external host (images, audio, fetch, iframes, scripts) needs that host added to the matching directive, or the browser blocks it. `script-src` keeps `'unsafe-inline'` because nonces would make pages dynamic (no PPR); hash-based SRI is the possible upgrade. Don't add `upgrade-insecure-requests` (it breaks `next start` on http://localhost). Check with `python3 .claude/skills/vibe-check/scripts/check.py <url> --only headers` (the `vibe-check` project skill).
- **Errors**: `PrismaExceptionFilter` maps P2002 → 409 and P2025 → 404. `PATCH` DTOs use `@IsOptionalNotNull()` (`common/validation.ts`) for non-nullable fields so `null` is a 400, not a 500. `POST /study/review` answers 409 when the card was rated concurrently (the client ignores it).
- **Email**: `MailerService` (`backend/src/mail/`, global module), Nodemailer over SMTP (`SMTP_*`, `MAIL_FROM`; Gmail App Password today). Without `SMTP_HOST`, outside production mail is only logged (handy for reading codes and links locally).
  - Verification and reset links (`auth/email-links.ts`, `auth/account-email.service.ts`): `/<locale>/verify-email#token=…` and `/<locale>/reset-password#token=…`. The token is in the **fragment** (never reaches a server); the page reads it and POSTs it. Verification needs a click (no auto-verify on load: mail scanners). `forgot-password` always answers 204. A reset verifies the email and signs out every session.
  - Emails contain **no user-chosen text** (not even the name): anyone can sign up with a stranger's address. Verification emails have a site-wide cap (`VERIFY_MAILS_PER_DAY` = 200/day, `account-email.service.ts`) so sign-ups can't use up the Gmail quota (~500/day) that resets and codes need.
- **Rate limiting**: `RateLimitService` (`backend/src/rate-limit/`, global): fixed windows in the `rate_limits` table, keys are `<bucket>:<sha256 of the id>`. `consume(...rules)` throws 429 (`retryAfterS` in the body); `hit(rule)` only reports (used for silent limits such as reset emails per address). The client IP comes from `common/client-ip.ts`; behind the frontend rewrite it is still the visitor's real IP (checked 2026-11-14 via `/api/health/db`, which needs `CRON_SECRET`, now also in the local `backend/.env`). Don't burst-test production from the dev machine: Vercel's firewall then challenges every request from that IP. Any new endpoint that sends email or checks a secret needs a limit.
- If the dev server keeps serving stale CSS after an edit, save the file again (a change written by a shell script was once missed by Turbopack's watcher).
- Dev servers started by Claude: stop them before ending the turn, or they hold 3300/4300 and the user gets `EADDRINUSE`. Stopping `nest start --watch` can leave its child `node dist/main` listening; check with `lsof -nP -iTCP:3300,4300 -sTCP:LISTEN` and kill by PID.
- When the user's own `npm run start:dev` is running, don't run `npm run build` in `backend/` (it deletes and rebuilds `dist/`, which their watcher runs from; on 2026-11-03 their server on 4300 stopped during such a build) and never `pkill` by a command pattern: stop only the PIDs you started. To test a backend build, start it from its own copy or restart theirs afterwards (a real content change in `src/` makes `nest start --watch` restart).
- **npm cache**: `~/.npm` on this machine has files with wrong permissions (EACCES). When installing packages, point `npm_config_cache` at a temp directory.
- `grep` in the shell is aliased to ugrep, which skips hidden/ignored files. Use `/usr/bin/grep` when searching `.env` or dotfiles.
- To check a Vercel build locally without logging in:
  - Create `<app>/.vercel/project.json` with `{"projectId":"local-test","orgId":"local-test","settings":{"framework":"nestjs"|"nextjs"}}`, then run `npx vercel@latest build --yes`.
  - Afterwards **delete `<app>/.vercel` (and `frontend/.next`)**: leftover output makes the next `next build` crash in Turbopack (`ModuleGraph::from_graphs_inner was canceled`).
- `prisma7.config.ts` must not throw when DB URLs are missing: `prisma generate` runs in `postinstall` on build servers.
