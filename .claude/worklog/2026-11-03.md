## Session 1: accounts, learning flow and a new app UI

### Request
- Rebuild the UI with these pages: user profile (name, gender, …), flashcards, learned words, home, not-learned words, plus any others that make sense. References: Cambridge Dictionary, Duolingo, Quizlet.
- Decisions asked and answered:
  - Scope: **full** (sign-up/sign-in, profile API, word API, SRS progress API, pages on real data).
  - Style: **switch to a learning-app look** (friendlier, more colour, big rounded buttons).
  - Extra pages: word + topic detail, learn new words, progress + settings, sign in / sign up.

### Decisions
- **Auth = database-backed sessions, not JWT + refresh** (PLAN.md §4 updated):
  - Server Components cannot set cookies, so an expired JWT could not be refreshed during server rendering.
  - Instead: a random token in the httpOnly `vocab_session` cookie (SameSite=Lax, 30 days, sliding once a day); only the SHA-256 hash is stored.
  - The `RefreshToken` model (an empty table) became `Session`.
  - Passwords hashed with argon2id (`@node-rs/argon2`, prebuilt binaries suit Vercel).
- **SRS: `ts-fsrs@5.4.2`.** 6.0.0 came out on 2026-10-28, too new to adopt.
- **Mastery levels** follow PLAN §3.6. "I already know this" counts as level 5 and is kept out of reviews.
- **Streak:** a day counts when today's cards (new + reviews) reach `dailyGoalCards` **or** today's active time reaches `dailyGoalMinutes`.
  - Active time is the sum of per-card time, capped at 60 s per card; there is no heartbeat yet.
  - A streak stays alive until the end of the next day.
- **Design**, using the `design-taste-frontend` skill (app screens; `editorial-greeting` style, seed 1195549931):
  - Taken from the skill's style: the greeting as h1 with today's one fact, a 12-column grid, tonal panels, soft 22px radius, pill controls, no shadows, gradients or emoji.
  - Adjusted to the user's choice of a friendlier look: one green accent with Duolingo-style chunky buttons (a solid darker lip, not a shadow), and a green mastery ramp on data.
  - Font: **Nunito**. The skill dealt Instrument Sans, which has no Vietnamese subset.
  - Product mark: two stacked flashcards with a tick.
- **Words lists:** one `/words` page with tabs (Not learned / Learned / Due / All); the nav has "Learned" and "Not learned" entries.
  - Levels are filters rather than a `/levels/[level]` route.

## Session 2: sign in with Google

### Request
- Add "Sign in with Google". The user created the OAuth client in Google Cloud (Web application, redirect URI `http://localhost:3300/api/auth/google/callback`) and put `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` in `backend/.env`.
- Asked about "Authorized JavaScript origins": not needed for a server-side flow; can stay empty.
- Asked to update `.env.example`.

### Decisions
- **Server-side OAuth 2.0 authorization code flow with PKCE (S256)**, no Passport and no Google script in the page.
  - `GET /api/auth/google?next&locale` sets a 10-minute httpOnly `vocab_oauth` cookie (state, verifier, next, locale; path `/api/auth/google`), then redirects to Google with `prompt=select_account`.
  - `GET /api/auth/google/callback` checks the state, exchanges the code, and verifies the ID token with `jose` (Google JWKS, issuer, audience = client id, expiry).
  - It then creates the normal session cookie and redirects to `/<locale><next>`. Errors redirect to `/login?error=google_*`.
- The callback lives on the **frontend origin** (first entry of `FRONTEND_URL`) and is proxied to the backend by the rewrite, so the session cookie stays first-party. No new env var besides the two Google ones.
- **Account linking:** by `googleId` first, then by verified email.
  - If the matching account's email was never verified (we don't verify emails at sign-up yet), its password is cleared and its sessions revoked, to stop account pre-hijacking. The owner can set a new password in Settings.
  - An email already linked to a *different* Google account → `google_conflict`.
- Google-only accounts:
  - `/me` returns `hasPassword` / `hasGoogle` (never the hash or the Google id);
  - "Set a password" needs no current password;
  - deleting the account is confirmed by typing the email.

### Work done
- Backend:
  - `src/auth/google.ts` and its tests (`google.spec.ts`, 7 tests: same-site `next`, PKCE, auth URL, code exchange, ID token signature/audience/issuer/expiry against a local JWKS);
  - controller routes; `AuthService.signInWithGoogle`;
  - `changePassword` with an optional current password; `DeleteAccountDto` takes `password` or `confirmEmail`.
- Frontend:
  - `GoogleButton` (Google's G mark) on sign-in and sign-up, with an "or" divider, and `?error=google_*` messages;
  - Settings: "Sign-in methods" (password / Google: on or not set up), a set-password mode, and delete by email;

## Session 4: a real word list from CEFR-J / Octanove + Wiktionary

### Request

### Decisions

  - Its content is © Cambridge University Press and only available through the Cambridge Dictionaries API, which needs an application and an Application Development Agreement.
  - Scraping the site is out. Documented in DATA_SOURCES.md and CLAUDE.md.
- **Word list and levels: CEFR-J Wordlist 1.5 (A1–B2) + Octanove Vocabulary Profile C1/C2**, from `openlanguageprofiles/olp-en-cefrj`.
  - CEFR-J: free for research and commercial use with citation (© Tono Lab, TUFS).
  - Octanove: CC BY-SA 4.0.
  - Credited in each word's `source` and in the footer. The raw lists are downloaded on each run and not committed.
- **Word content: Wiktionary and the other open sources**, through the existing `words:enrich`.

### Work done
- `scripts/words/build-cefrj.ts` (`npm run words:cefrj`):
  - downloads both lists through the HTTP cache;
  - maps CEFR-J's CoreInventory / Threshold labels to our topic slugs;
  - keeps the first spelling of variants, keeps case (March / march), keeps the lower level for duplicates;
  - skips contractions, inflected be/do/have and the articles;
  - reuses the 53 curated sample words' content;
  - writes `scripts/words/out/cefrj-<level>.json` (gitignored).
  - Result: 9,757 words (A1 1,148 · A2 1,407 · B1 2,446 · B2 2,778 · C1 1,045 · C2 933); about 2,130 have a topic.
- `lib/http.ts`: a per-host queue keeps the minimum gap between request starts when words run concurrently; a `shouldCache` filter.
  - First version of the queue called itself recursively (a replace hit the new function instead of the old loop); caught by oxlint's unused / only-used-in-recursion warnings and fixed.
- `enrich.ts`:
  - `--concurrency N` (default 4, keeps the input order);
  - `level_source` credited first in `source`;
  - MyMemory "quota used up" answers are never cached, and further MyMemory calls stop for the run;
  - Vietnamese meanings are cleaned (`cleanMeaningVi`: HTML entities, whitespace, stray punctuation, copies of the English word).
- Tests: 40/40 (builder mapping and skip rules, meaning cleanup). Lint clean.
- Docs: DATA_SOURCES.md §1 and §3 (sources, licences, how the builder works, the quality caveats, the quota note), README, CLAUDE.md, footer credit (vi/en).

### Findings (40-word A1 trial, about 2 s per word with concurrency 4; Tatoeba's 1 request/s is the bottleneck)

- Some Vietnamese meanings belong to another sense (afraid → "đáng sợ").
- Function words get grammar-style definitions.
- Usable as a base, but not as good as the hand-reviewed sample.
