## Session 2: root cause of the backend hang; speaking features added to the plan

### Backend hang
- Symptoms: every path on `vocab-learning-eight.vercel.app` hung, even `/favicon.ico`; the Runtime Logs were empty; the Framework Preset was NestJS.
- Ruled out:
  - a Vercel incident: the status page said "All Systems Operational";
  - the code: the bundle from a local `vercel build`, run with plain `node` and production env, answered 200.
- **Root cause**: `@vercel/node` loads the entry in `compileUserCode()` (`dist/bundling-handler.js`). It replaces `http.Server.prototype.listen` with a stub that only captures the server and returns, and the `listening` callback never fires. Then it `await`s loading the module before it serves anything.
  - `src/main.ts` ended with `await bootstrap()`, and Nest's `app.listen()` waits for that callback.
  - So loading the module never finished, and every request hung. This had probably been the case since the first deploy; the backend had never been reachable, because the frontend also lacked `API_URL`.
- **Fix**: `bootstrap().catch(… process.exit(1))` without a top-level `await`.
- Verified with a harness that copies that launcher logic (`launcher-harness.cjs` in the scratchpad):
  - the old ending → "module never finished loading";
  - the new one → the module loads and `/api/health` answers 200.
- 56 unit tests pass; lint is clean. Added the rule to CLAUDE.md.
