# 2026-11-12

## Session 1: production /api broken after deploy

### Findings
- `https://godee.vercel.app/api/*` returned `DNS_HOSTNAME_RESOLVED_PRIVATE`: the frontend had been built without `API_URL`, so the rewrite pointed at `http://localhost:4300/api`. The user added `API_URL=https://vocab-learning-eight.vercel.app/api` to the frontend project.
- The backend's production domain (`vocab-learning-eight.vercel.app`) does not answer at all: `/api/health` hangs for more than 60 s, although that route doesn't touch the DB.
  - The same compiled code, started locally with `NODE_ENV=production` and only the three env vars the Vercel project has (`DATABASE_URL`, `DIRECT_URL`, `FRONTEND_URL`), answers 200 at once.
  - So the hang is on the Vercel side: build output, runtime or configuration. Waiting for the backend's Runtime Logs from the user.
- Because of that hang, the next frontend build failed: the landing page's `'use cache'` `landingData()` waited on the backend until Next.js aborted the prerender ("A "use cache" function took too long").

### Fix
- `frontend/src/lib/api.ts`: public fetches (`apiGet`, `getTopic`) now give up after 10 s (`AbortSignal.timeout`). The landing page already falls back to empty data on errors.
- Verified: `next build` with `API_URL` pointing at a local server that accepts connections but never answers → all 51 pages generated. Typecheck and lint are clean.
