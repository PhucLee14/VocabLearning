## Session 3: email abuse fix (audit RATE_LIMITING #2)
- Emails no longer contain any user-chosen text: `linkMail(locale, kind, url)` and `codeMail(locale, action, code)` lost their `name` parameter and greet with "Chào bạn," / "Hi,". Reason: anyone can sign up with a stranger's address, then the stored name reached that stranger in verification, reset and code emails sent from our Gmail.
- Site-wide cap on verification emails: `VERIFY_MAILS_PER_DAY = 200` per 24 h (`verify-send:site` rule in `AccountEmailService.sendVerification`), checked after the per-user limits so refused requests don't count. Over the cap, sign-up still succeeds (`sendVerificationQuietly` logs it) and the resend button gets 429, which the UI already shows as "too many tries, wait a while". This keeps ~300/day of the Gmail quota for resets and codes.
- Tests: new `account-email.service.spec.ts` (order of limits, refused-per-user not counted, over-cap sends nothing); `email-links.spec.ts` / `confirm-code.spec.ts` now check the fixed greeting. 60/60 tests pass; tsc (only the existing `supertest/types` error) and oxlint clean.
