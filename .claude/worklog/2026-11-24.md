### Decisions
- **Error boundaries per route group**, so the frame survives the error:
  - `(site)/error.tsx`: under the site header.
  - `(app)/error.tsx`: inside the app shell, so the sidebar still works.
  - `[locale]/error.tsx`: for errors in those layouts themselves. It stands alone, with the logo.
- **`app/global-error.tsx`** catches errors in the root `[locale]/layout.tsx`.
  - It brings its own `<html>`, `globals.css` and the theme init script.
  - Its text is in both languages, since no translations are loaded there.
  - "Home" is a plain `<a>`, for a full reload. The ESLint rule is disabled on that one line, with the reason.
- **404**:
  - `[locale]/not-found.tsx`: logo, "404", title, text and a "home" button.
  - `[locale]/[...rest]/page.tsx` calls `notFound()`, so unknown addresses under a locale reach that page.
  - "Home" is `/`. `proxy.ts` sends signed-in visitors on to the dashboard.
- **Shared view**: `components/error-view.tsx`.
  - It shows the error code (`digest`) when there is one, so it can be matched with server logs.
  - It logs the error to the console.
  - "Try again" calls `retry()`, Next 16's recommended prop (checked in `node_modules/next/dist/docs` and in `error-boundary.d.ts`).
- **New messages**: the `Errors` namespace in `en.json` and `vi.json`.
- **Not done**:
  - No metadata title for the 404. Only the root `not-found` supports metadata, and a React `<title>` would duplicate the layout's.
  - `global-not-found` is experimental and not needed: every address gets a locale prefix from the proxy.
