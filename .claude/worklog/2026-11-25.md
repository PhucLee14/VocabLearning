### Part 2: Phase 3a
Decisions:
- One `AdminModule`, one controller under `/api/admin/*` with `SessionGuard` + `AdminGuard` (role read from the DB with the session, so a demotion is immediate). Non-admins get 403 from the API and our 404 page in the frontend.
- Audit log table `audit_logs` (actor, action, target type/id/name, changed fields as `{field: [before, after]}`), written in the same transaction as the change where possible.
- Users: list/search/filters, detail (study counts, 30-day bars, signed-in browsers), role change, disable/enable (revokes sessions; sign-in then 403), sign out everywhere. An admin can't change their own role or disable themselves (no lock-out by accident).
- Words: list with filters (level, part of speech, topic, open reports), create, edit (slug never changes), delete (notes keep the headword as title), merge a duplicate into another entry with the same headword (cards: the one with more reps wins; notes joined; new examples, topics, review history and reports moved).
- Topics: tree, create, edit, move under another top-level parent, reorder (up/down), delete (only without subtopics). Public pages cache topics for hours; said on the page.
- Import: preview → commit. The browser reads the file and sends its text; the server stores only its SHA-256 and the counts in `import_jobs`, and the commit must send the same text, by the same admin, within an hour. Max 5,000 rows / 3.5 M characters; `/api/admin/import` alone accepts 4 MB bodies. Writing is batched (100 words per transaction: an upsert each, then four bulk statements), shared with the CLI in `src/words/import/write-words.ts`.
- Feedback: `feedback` table (type, word, message, page path, status, reply, replied by/at, reply seen at). Learners: "Send feedback" in the sidebar, "Report a problem" on the word page and the flashcard back, a "My feedback" page with replies (count in the menu). Admins: inbox with status/type/word/user filters, status + reply, optional "you have a reply" email (fixed text and a link only, verified addresses, 100/day site-wide).
- Dashboard: users, active learners (7 days), words, open feedback, and a 14-day table (learners, cards, sign-ups).
- First admin: `npm run admin:role -- <email>` (writes an audit row with no actor).
- All new UI text in `en.json` and `vi.json` (`Admin`, `Feedback` namespaces, plus `Nav.admin`, `Nav.feedback`, `Auth.errorDisabled`, `Auth.error_google_disabled`).

Problems:
- **Body parser**: the 4 MB parser for the import route was first `app.use('/api/admin/import', json(...))`. Nest skips its own global JSON parser when a middleware named `jsonParser` is installed, so every other route got an empty body (a 2 MB login gave 400 "password must be a string" instead of 413). Fixed by wrapping it in a function named `adminImportBody`; re-tested: 2 MB login → 413, 2 MB import without a cookie → 401 (body parsed, guard reached). Noted in CLAUDE.md.
- Decorators can't sit on `declare` fields, and a subclass can't make an `@IsOptionalNotNull` field required (the parent's `ValidateIf` still applies), so create and update share one DTO and the services check the required fields.
- Applying the migration to Neon was blocked by the permission classifier (dev and prod share one database). Docker is installed but its daemon wasn't running, so there was no local Postgres either.
